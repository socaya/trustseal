Trust, Security & eIDAS 2.0 Standards

TRUSTSEAL implements end-to-end electronic signature assurance across Simple (SES), Advanced (AES), and Qualified (QES) tiers, backed by ETSI PAdES long-term archival sealing, RFC 3161 trusted timestamps, Remote QSCD (CSC API v2), and EUDI Wallet identity verification.

Supported eIDAS 2.0 Electronic Signature Levels

Every document sent through TRUSTSEAL can enforce per-recipient assurance tiers matching EU Regulation 2024/1183 (eIDAS 2.0), Regulation (EU) No 910/2014, ESIGN, and UETA.

ETSI EN 319 142 PAdES Long-Term Preservation Profiles

  • PAdES-B-B (Baseline): Embedded CMS/PKCS#7 cryptographic signature (`ETSI.CAdES.detached`) over the exact PDF ByteRange backed by HSM / AWS KMS or QTSP signing keys.
  • PAdES-B-T (Trusted Time): Binds an RFC 3161 Time-Stamp Authority (TSA) token to the signature value for independent cryptographic proof of signing time.
  • PAdES-B-LT (Long-Term Validation): Embeds the complete certificate chain, OCSP responses, and CRL revocation snapshots inside the PDF `/DSS` and `/VRI` dictionaries for offline verification beyond certificate expiry.
  • PAdES-B-LTA (Long-Term Archival): Applies periodic `ETSI.RFC3161` Document Time-Stamps sealing both the signature and all DSS validation material for multi-decade archival preservation.

Remote QSCD (CSC API v2.0) & EUDI Wallet Architecture

  • Cloud Signature Consortium (CSC) API v2.0: Standards-compliant credential discovery (`/credentials/list`), SCAL2 Signature Activation Data sole-control authorization (`/credentials/authorize`), and remote HSM hash signing (`/signatures/signHash`).
  • EUDI Wallet ARF (OpenID4VP / OID4VCI): Generates verifiable `openid4vp://` presentation requests for EU Person Identification Data (PID) at Level of Assurance High and executes Wallet-backed Qualified Electronic Signatures bound to exact document SHA-256 digests.
  • ETSI EN 319 412-5 QCStatements Inspection: Automated X.509 parser validating `QcCompliance` (`0.4.0.1862.1.1`), `QcSSCD/QSCD` (`0.4.0.1862.1.4`), and `QcType` (`esign` / `eseal`) extensions against EU Trusted Lists (LOTL).
  • Tamper-Evident Audit Chain & Certificate of Completion: Every workflow action — creation, dispatch, viewing, OTP/EUDI verification, signing, and PAdES sealing — is chained with SHA-256 hashes and exported in a verifiable Certificate of Completion.

Independent Public Verification

  1. Upload any sealed PDF or enter a TRUSTSEAL Package Reference (`ESIG-...`), Document SHA-256, or Stamp Receipt ID.
  2. TRUSTSEAL verifies the exact byte digest, embedded PAdES CMS signature, certificate chain, RFC 3161 TSA token, and OCSP/CRL revocation status.
  3. The verifier returns a structured cryptographic report detailing the eIDAS 2.0 level (`SES`/`AES`/`QES`), ETSI PAdES profile, and hash-chain integrity.
